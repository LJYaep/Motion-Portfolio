# Activate enquiry email and Discord notifications

The backend is implemented, but **live sending is not activated** until your
private SMTP settings are configured. No passwords, webhook tokens or live
customer data are included in this package.

## 1. Configure email

Copy `server.env.example` to `server.env` in the website folder. Enter the
credentials for the mailbox or SMTP service that will send the messages.
The default configuration uses Gmail SMTP with STARTTLS on port 587:

```ini
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_SSL=false
SMTP_USERNAME=daniljy.aep@gmail.com
SMTP_PASSWORD=your_generated_app_password
SMTP_FROM=daniljy.aep@gmail.com
```

For Gmail, use a Google app password when available, not your normal Google
account password. Google requires 2-Step Verification for app passwords.
Create one privately at https://myaccount.google.com/apppasswords and put it
in `server.env` on the server. Do not paste credentials into chat, HTML or JS.
If app passwords are unavailable on your account, use another authenticated
SMTP provider and update the same settings. The sender must be authorised by
the SMTP account/provider.

Each accepted enquiry creates three independent email deliveries:

1. Complete enquiry details to **daniljy.aep@gmail.com**.
2. Complete enquiry details to **denial.aep@gmail.com**.
3. A receipt/reference email to the visitor's submitted email address.

Owner notifications set Reply-To to the visitor. The visitor confirmation
sets Reply-To to daniljy.aep@gmail.com and does not repeat arbitrary message
text. Confirmation delivery may take time; a successful form submission means
the enquiry is durably queued, not that every email has reached an inbox.

Start `START-WEBSITE.bat` on Windows, or run `python3 start-website.py`.
The console reports whether email is configured. Restart after editing env
settings. Until SMTP is configured, the server rejects submissions with an
honest unavailable message; it does not pretend to have sent an email.

## 2. Enable optional Discord alerts

A Discord incoming webhook is sufficient; a full bot account is not required.
Create a webhook in the private channel where you want enquiry notifications.
Then configure these private server settings:

```ini
DISCORD_WEBHOOK_URL=https://discord.com/api/webhooks/YOUR_WEBHOOK_ID/YOUR_TOKEN
DISCORD_NOTIFY_USER_ID=YOUR_NUMERIC_DISCORD_USER_ID
```

Use the actual webhook URL generated by Discord. With a valid numeric user ID,
the notification mentions only that user. Without it, the channel gets an
ordinary notification message. Customer input cannot create @everyone or role
pings. Discord notification failure does not cancel the enquiry or email jobs.
Only the name, service, reply preference and reference are sent to Discord;
the complete enquiry goes to your two inboxes.

For the **public Discord contact button**, set a profile link or fresh server
invite, separately from the secret webhook:

```ini
DISCORD_CONTACT_URL=https://discord.com/users/YOUR_USER_ID
```

Until a public link is configured, the button says **Discord reply** and
selects Discord as the form's preferred contact method, asking for the
visitor's username. No old or unverified invite has been restored.

## 3. Instagram contact

The Instagram button opens https://www.instagram.com/ljyaep/.
Visitors can also choose an Instagram reply and enter their handle in the
form. Their email remains required for the submission confirmation.

An automatic Instagram DM bot is **not activated or included**. Meta's
messaging API requires an Instagram professional account, app permissions and
an authorised conversation; it is not a general-purpose channel for sending
arbitrary form notifications to any Instagram user. Use Discord webhooks for
form alerts. A separate Meta integration can be added once the professional
account and API access are available.

## 4. Publish with the backend

Static HTML hosting alone cannot process SMTP email or run the outbox worker.
Host the Python application with persistent storage and outbound SMTP access.
The Windows launcher is for local development. For public hosting, install
the production WSGI server and run:

```sh
python3 -m pip install -r requirements.txt
waitress-serve --listen=127.0.0.1:8080 --max-request-body-size=16000 --call application:create_app
```

Put it behind your hosting provider's HTTPS reverse proxy. Keep the real
client IP/Host settings configured through the provider's trusted-proxy
configuration, rather than trusting arbitrary forwarded headers. Preserve
the existing referrer policy for YouTube playback.

The simplest deployment serves pages and `/api/enquiries` from the same
domain. If the frontend is on a different domain, change `enquiryEndpoint`
in `script.js` to the backend URL and set `ALLOWED_ORIGINS` on the backend to
the exact frontend HTTPS origin. No wildcard CORS origin is enabled.

`ENQUIRY_DB_PATH` can point to a persistent SQLite file outside the website
folder. The default is `data/enquiries.sqlite3`. Keep it private and back it
up if retaining client enquiries. The server serves only the five HTML pages,
CSS, JavaScript and approved asset files. Environment files, the database,
backend source and tests return 404 over HTTP.

Do not include `server.env`, `data/`, tokens or database copies in a public ZIP
or static-file upload. The supplied ZIP contains only an empty env template.

## 5. Delivery and verification

The durable outbox retries temporary failures with backoff, up to eight
attempts per delivery. Failed jobs stay in the private database, with the
error type logged in the server console. Each delivery is tracked separately,
so successful owner emails are not routinely repeated when another delivery
fails. As with other SMTP outboxes, a lost acknowledgement after acceptance
can still cause a duplicate; this is not an exactly-once mail guarantee.

The form uses an idempotency key to prevent ordinary double clicks and network
retries from creating duplicate enquiries. Server validation, a honeypot,
same-origin checks and hourly rate limits are included. Visitors can still
copy/download an enquiry or open their email app if submission fails.

Run the included backend tests without sending real email:

```sh
python3 -m unittest discover -s tests -v
```

All SMTP and Discord transports in these tests are mocked. Live delivery and
notification permissions must be checked after credentials are configured.
